Train/Test Split

For reproducibility, we will set a seed here. Then, we will split our data into a training set and a test set. We do not want to train our model on the entire 2011 observations, so we will split them into two different sets. We want the sets to have similar propertion of Potability and Not Potable water, so we will strata the data based off of Potability status.

5-Fold Cross Validation

In order to create our models, we will create a 5-fold cross validation, also stratified based on Potability status. This will ensure that each fold has at least similar proportion of Potable and Not Potable water observations to train our models.

water_folds <- vfold_cv(
  water_train,
  v = 5,
  strata = Potability
)
water_recipe <-
  recipe(Potability ~ ., data = water_train)

Classification Tree

A classification tree is a supervised learning algorithm used when the response variable is categorical. In our case, Potability, is our response variable. The algorithm recursively partitions the predictor space by selecting variables and split points that best separate the classes. Beginning at the root node, observations are divided into increasingly homogeneous groups until a stopping criterion is met. Each terminal node predicts the class that is most common among the training observations in that region.

One of the main tuning parameters is the complexity parameter (cost complexity). Larger values produce smaller, simpler trees by penalizing additional splits, while smaller values allow more complex trees that may better fit the training data but increase the risk of overfitting. Cross-validation is used to identify the complexity parameter that provides the best balance between model complexity and predictive performance.

Random Forest Model

A random forest is an ensemble learning method that builds upon the basic classification tree. This should mean it predicts better in the end! Instead of constructing a single tree, a random forest grows hundreds of decision trees using bootstrap samples of the training data. At each split, only a random subset of predictors is considered, increasing diversity among the trees. Final predictions are obtained by combining the predictions from all trees through majority voting.

Because individual trees are highly variable, averaging many trees substantially reduces prediction variance while maintaining low bias. This generally results in better predictive performance and greater resistance to overfitting than a single classification tree.

The primary tuning parameter considered here is mtry, which controls the number of randomly selected predictors considered at each split. The larger mtry is, the more predictors are used.

Random Forest Model Building

We want to tune mtry, but we will set the number of trees to 500.

rf_model <-
  rand_forest(
    mtry = tune(),
    trees = 500,
    mode = "classification"
  ) |>
  set_engine("ranger")
rf_workflow <-
  workflow() |>
  add_recipe(water_recipe) |>
  add_model(rf_model)

Because we have a maximum of 9 predictors, we will set mtry to be anything from 1 to 9 when we train our models and see which value of mtry gives us the best result.

rf_grid <- tibble(mtry = 1:9)

The classification tree and random forest models were both tuned using five-fold cross-validation with multinomial log-loss as the evaluation metric. On the independent test set, the classification tree achieved a log-loss of 0.682, while the random forest achieved a lower log-loss of 0.602. Because lower log-loss indicates better predictions, the random forest outperformed the classification tree. This result is consistent with the cross-validation results, where the random forest also achieved the lowest average log-loss, suggesting that aggregating predictions across many decision trees produced better generalization than a single classification tree.
